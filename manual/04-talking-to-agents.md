# 4 · Talking to agents

*Croo Operator's Manual · v1.0.1 · 2026-10-13*

**The one thing to know: the quality of what you get back is set by the
brief you give.** Croo makes the giving easy — text, files, images,
saved prompts, drafts — so the thinking is the only hard part left.

## The chat

Every agent reads the same way: your messages and its replies, in a
clean chat view, whatever engine is underneath. This is Croo's chat
mode — Gamma — and it's built on a simple idea: you talk to an agent
like you talk to a person, so the reply should read like one. Easy to
read, easy to answer, the same for every agent.

Two more views sit behind it when you want them: Echo shows the
original — the engine's raw terminal, untouched — and Beta is the
tidied terminal in between. Most days you'll live in Gamma and glance
at Echo when you want to see exactly what the engine said.

Type in the input box and send. Attach files, drag and drop, or paste a screenshot straight
in. Paste something long and Croo turns it into an attached file
automatically, so the conversation stays readable.

Each message in the chat has its own small controls: copy it, attach it
to your reply, or forward it to another agent — handy when one agent's
answer is exactly the context a colleague needs.

## One-click answers

When an agent offers choices — a numbered menu, an approval, options —
the choices appear as buttons. One click answers. You'll meet this
constantly: agents ask before anything that needs your word, and Croo
keeps saying yes cheap. And when a stretch of work is nothing but
routine yeses, Power-Through can press them for you for a window you
choose — many one-clicks, handled (chapter 7).

## Macros — the prompts you reuse

Anything you find yourself typing twice, save as a macro. Scope it to a
single agent, a project, an engine, or everywhere, and use blanks that
fill in the agent or project name on the fly. One macro — your pick —
can be pinned to the input pane, on web and phone, one tap away.

Good macro candidates from real use: your daily status ask, your
test-before-handover reminder, your "write me a bug report" request.

## Pinned drafts and recents

An agent is busy? Keep thinking. Write the next instruction, attach the
files it needs, and pin it for later. Every agent keeps its own list of
pinned drafts — use it as that agent's to-do if you like: the queue of
work you'll hand over as it frees up. And your last ten inputs stay on
recall, so re-sending or reworking a recent instruction is a pick, not
a retype.

## Tidy my draft

Wrote it in a hurry? One button rewrites what you've typed into a
cleaner message — with undo. It runs on the local AI on your own
machine, so a rough draft never leaves your desk to get tidied.

## Writing briefs agents act on well

The habits that pay, in rough order of payoff:

1. **Say what "done" means.** Don't just name the task — state how
   you'll judge it. "Add login" leaves the agent guessing where to
   stop. "Add login; it's done when a signed-in user sees their own
   name, and there's a test for a wrong password" gives it a finish
   line — and you a way to check the work.
2. **Attach the context, don't describe it.** The error message, the
   sketch, the sample file. Agents read attachments well; summaries of
   attachments, less so.
3. **One job per brief.** Three asks in one message come back as one
   muddled answer. Three briefs come back as three results.
4. **Put standing instructions in the identity, not the chat.** If you
   find yourself repeating a rule, it belongs in the agent's identity
   file (chapter 3) — said once, honoured always.
